# 宜必购盲盒系统 · 前端设计规范 v2（mobile-first）

> 适用页面：顾客 H5（手机端优先）/ 商家后台（手机优先 + PC 兼容降级）/ 平台后台（手机优先 + PC 兼容降级）。
> 这次是 V1 美化稿后的重设计：基准 375px，>= 768px 容器居中。
> 设计原则：**功能完整 = 禁止缺 Tab / 禁止假按钮 / 全部走 API**。

## 1. 响应式断点

```
--bp-xs: 320px;     /* 极小屏（iPhone SE 1） */
--bp-sm: 360px;     /* 主流 */
--bp-md: 375px;     /* 设计基准 */
--bp-lg: 414px;     /* 大屏手机 */
--bp-xl: 768px;     /* 平板 / PC 兼容起点：在此宽度起切换为居中容器 */
```

- 默认容器：手机宽度（mobile-first），单列纵向。
- >= 768px：容器 `max-width: 720px`（顾客端 640px、商家/平台 720px/1080px），水平居中；背景换深灰突出卡片。
- 不出现横向滚动条；底部 Tab（顾客）始终固定。

## 5. 移动端核心组件

### 5.1 按钮 `.btn`
- 移动端**主操作 48px 高 / 次操作 40px / 输入 46-48px**，padding 0 18px。
- 主色填充 / 16px 字 / 600 / 按下 `scale(.98)`。
- `.btn--block` 全宽主操作。
- 触屏 hit-area ≥ 44 × 44px。

### 5.2 输入 / 选择
- 高度 46–48px，padding 0 12-14px，圆角 `--r-md`。
- 聚焦：边框主色 + `--sh-press` 发光。
- 表单 label 字号 13，margin-bottom 4。

### 5.3 卡片 `.card`
- 圆角 14，padding 18，背景 surface，shadow-1。
- 标题 + 右上角操作（`.sec .sp`）。

### 5.4 列表项 `.list-item`
- 单行高 56-72px（多行换行），padding 12px 0，flex 三段（main + v + ops）。
- 分割线 1px divider；移动端多行内容也可读。

### 5.5 Tag / 状态徽章 `.badge` / `.pill`
- 圆角 pill，11-12px，semantic 5 色（success/warning/danger/info/neutral）。

### 5.6 顶部栏 `.top`
- 商家/平台：sticky 渐变背景 + 左 logo + 右 logout/通知/告警。
- 顾客部分页面有 hero 渐变区（非 sticky，单独顶出 24px 圆角）。

### 5.7 Tab 三种模式
- **顾客**：底部固定 Tab（3 个：抽盒/钱包/商城），高度 56px + safe-area。
- **商家/平台**：顶部横向滚动 chip tab；手机：可横滑 7-8 个 Tab；PC（>=768px）：顶部水平 tab + sticky。

### 5.8 Toast / Modal
- Toast：顶部居中浮出 3s；success/warning/danger/info 4 色。
- Modal（顾客）：底部 sheet 滑入，最大 520px 宽（V2 新增）。
- Modal（后台）：居中弹窗，mobile 最大 90vw。

### 5.9 加载 / 空状态 / 错误
- Loading：旋转 SVG + 「加载中…」。
- Empty：emoji + 文字 + 居中样式。
- Error：toast 或 warn 条 + 「重试」。

### 5.10 表格（后台）
- 手机完全**用卡片列表（`.list-item`）替代**横向表格；
- PC（>=768px）：水平表格，仅当窄屏折叠。
- 列标签 + 值用 chip 和换行表达。

### 5.11 数字输入与键盘
- 金额：`inputmode="decimal"` + `step="0.01"`；
- 手机号：`inputmode="numeric"` `maxlength="11"`；
- 二维码 / 扫码：调用 `qr-svg` API + 摄像头识别（jsQR 1.4，V2 降级到手动输入）。

### 5.12 二维码块
- `.qrbox`：宽 220px，padding 10 圆角 14 背景。
- 调用 `POST /api/.../qr-svg` 拿 svg 字符串内联展示。

## 6. 页面模式

### 6.1 顾客抽奖流
1. 进入 → 自动登录（如已有 token）→ 看到 hero + 抽盒按钮；
2. 抽盒 → 中奖弹窗（sheet 滑入）→ 「查看钱包」/「再抽一次」；
3. 团购登记：渠道 + 金额 → 直接登记；
4. 本店下单：选模式A/B → 试算 → 下单 → 模式A展示收款码 / 模式B生成凭证码。

### 6.2 钱包
- 顶部余额 + 快捷两按钮（动态码 / 身份码）；
- 三段：优惠券（可核销/已使用/已过期）+ 余额流水 + 消息中心。

### 6.3 宜必购商城
- 商品列表 → 选券 + 选余额 → 下单 → 订单列表 → 全额退款（弹窗确认）。

### 6.4 商家 8 Tab（V2 增了"概览"Tab，按移动友好顺序）
1. **概览**（订单数/营业额/待确认/会员状态 + 最新播报）
2. **奖品池**（门店抵扣参数 / 收款码上传 / 权重 / 私有档位 / 公共池 / 本店二维码）
3. **专属盲盒**（美团/饿了么档位 + 大类权重 + 专属二维码）
4. **手工核销**（券核销 / 余额扣减 / 摄像头扫码 / 动态码+身份码+凭证核验）
5. **流水报表**（余额流水 / 团购登记 / 宜必购对账，+ Excel 导出）
6. **外来券**（只读 + 导出）
7. **会员续费**（状态 / 套餐 / 续费 / 订单 + 测试确认）
8. **订单收款**（订单列表 + 录流水号 + 标记退款 + 导出）

### 6.5 平台 7 Tab（按移动友好顺序）
1. **概览**（商家数 / 未处理告警 / 优惠券 / 有效会员）
2. **商家管理**（新增校验 + 启用/重置密码/删除带管理员密码）
3. **全局参数**（balance_deduct_rate / ibigou_channel_switch / 微信支付 7 项 + test_pay_confirm_enabled）
4. **公共池**（大盘 + 导出）
5. **报表**（券/流水/团购/宜必购 + Excel 导出）
6. **审计会员**（会员列表 / 调整有效期 / 续费订单 / 审计日志 + 撤销）
7. **告警**（列表 + 标记处理 + 概览预览）

## 7. 动效 / 触感

- 渐入：`opacity 0→1` + `translateY 8→0`，220ms `cubic-bezier(.2,.7,.2,1)`。
- 按钮按下：`scale(.98)`，120ms。
- 弹窗（顾客 sheet）：从底部 30% 滑入，260ms `cubic-bezier(.2,.7,.2,1)`。
- 抽奖中奖：emoji 表情跳跃 + 礼花字符喷洒；`navigator.vibrate(80)`。
- `prefers-reduced-motion: reduce` 降级。

## 8. 安全

- 全部 token 存 localStorage；失效时统一 401 → 跳登录（顾客/商家/平台三端登录页）；
- 删除/重置密码等敏感操作**二次确认**（弹窗验证管理员密码）；
- 金额输入校验 + 服务端二次校验（前端信任不可全信）。

## 9. 工程约束

- 文件 UTF-8 **无 BOM**；字体栈以系统栈开头；
- 内嵌 JS 用**模板字符串**承载多行，禁止 `\n` 字面量；
- 不依赖外部 CDN（jsQR 降级到手动输入）；
- 所有页面能**完全离线运行**（除 API）。

## 10. V2 修复的 V1 已知问题

| 问题 | V1 表现 | V2 修复 |
|---|---|---|
| 商家端 dcMode 重复 id | 模式 B 选项无法保存 | 删除重复 id；保留 1 个有效 select |

| 商家订单无退款入口 | 任务单要求缺失 | 订单列表行加「标记退款」按钮（弹窗 confirm） |

| 顾客端请求体错用 JSON | 改为 form-urlencoded 才对（与后端 `@RequestParam` 契约一致） | 全部 `URLSearchParams` 表单 |
| 表单输入框 14px | iOS 自动放大 | 全部 16px |
| 表格在手机端挤压 | 商家/平台订单列表 | 改为 `.list-item` 卡片 |
