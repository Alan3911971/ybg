物业 Agent · 主动服务

物业不是不想服务，是没人盯：20 个模块、每天 7 件事，全靠人记，必漏；业主不是要个聊天机器人，是想知道「我该交什么、我报的修到哪了、我能不能进、社区有啥」。所以这套东西的形态是「AI 先办，物业点头，业主点一下」。

★ 这一页只有两区：物业端 17 屏 + 业主端 15 屏上区是物业内部工具（今日台 / 对话 / 模块全景 / 主动规则 / 触达闭环 / 工单 / 收费 / 商户审核 / 设备告警 / 门禁车行 / 社区经营），业主和商家都看不到；下区是业主微信 H5。物业这套覆盖 14 个域 39 项能力（58 个真实路由 + 本轮新增的业主群受理与邻里互助撮合），按「AI 全办 / 起草你点头 / 只能你做」分三档，手机版只呈现今天要动的那几件。每个核心域两屏：一屏看全局，一屏能直接办（工单→派单打分、收费→单户账单与减免、告警→规则阈值、巡检→扫码打点、经营→场地退改、权限→角色矩阵）。商家侧不单独出稿——业主跟老板谈妥后，AI 在业主端出一张邀请码，老板扫码自己注册，注册成功就等于有了商家后台账号，直接进已有那套后台（本小区 12 家存量商户用的同一个，不新做、不并行）。所以商家那一侧我们只补「注册入口」，其余一行代码都不用改。业主端把老小程序的商城 / 抽盒 / 收银台 / 订单 / 我的全部并了进来（原 customer-* 11 页一页不丢），并且做了口径打通：商城实付 ×8% 分账进物业钱包 → 只能抵物业费；抽盒最高奖也改成物业费抵扣券——消费越活跃，物业费缴得越少，这条链才转得起来。
★ 物业费不是催出来的，是抵出来的业主在小区商户消费 → 分账结算 → 钱包余额 → 自动抵扣物业费；缴费前还能抽一次盲盒（奖品商户出，物业零成本）。催缴只是兜底，主路径是抵扣。
① 一件事，两份说法，一个引擎电梯离线：物业收到「派单+历史故障」，128 户收到「明天 10–12 点停梯，请走 1 单元」。同一个事件，说给两种人听。
② 主动不是推消息，是提前把事办了账单到期不是发提醒，是「单子已生成 + 一个缴费按钮」；报修不是让业主填表，是识别完直接给三个时段。
③ 打扰预算写死在引擎里每户每周 ≤3 条服务通知、营销 0 条混入、21:00–08:00 不发。靠物业自觉的频控等于没有。
★ 物业管理的完整面，别缩成 5 个页面账单收费、工单、设备告警、设施巡检、门禁人脸、车辆访客、场地预约、增值服务、社区活动、商户分账、钱包抵扣、盲盒奖池、组织房屋——13 个域 37 项，全部有对应接口与表（PropertyBill / PropertyWorkorder / PropertyDevice / PropertyDeviceAlert / PropertyInspection* / PropertyAccessLog / PropertyVehicle* / PropertyReservation / PropertyValueService / PropertySplitRecord / PropertyPrizePool …）。缺的不是功能，是排序。
④ 涉钱、涉隐私只出草稿减免退款双人确认；独居老人只提示「3 天没刷卡」，不代联系家属；人脸原图、手机号按角色过滤在工具层。
不做的事不做闲聊管家、不做万能搜索、不替物业定收费政策——这三样业主不用，物业不敢。

★ 业主邀商家 = 一张码把商家送进已有后台，不是个人拉客业主出「发现」+ 商家出「让利 8%」+ 物业出「审核与背书」。业主的「瞬间到账」拆成两段：审核通过即刻 ￥30（敞口小、防刷），首单满 ￥100 且 7 天无退款再补 ￥70。商家信不信，靠五张凭证：盖章电子协议、特约商户铜牌、业主端曝光位、每月对账单、后台可见的推荐人+审核人。同类目每小区封顶 2 家——没有这个保护，先入驻的商家第二天就退。
