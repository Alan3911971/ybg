## 四、与 V1.4 冲突的文档变更点（以最终定稿为准）

1. **余额抵扣比例**：V1.4 平台全局 `balance_deduct_rate` → 定稿**门店独立配置**（可填 0 禁抵扣）
2. **抵扣上限**：V1.4 无单日上限 → 定稿新增**本店单人单日抵扣总上限**
3. **抵扣计算**：V1.4 用户手输抵扣金额 → 定稿**全自动**（四重 min 条件）
4. **退款**：V1.4 支持全额+部分 → 定稿**仅全额**
5. **收款闭环**：V1.4 用户 H5 提交订单 → 定稿模式 A（H5 提交）**或**模式 B（商家端 H5 确认完成）
6. **商家端**：V1.4 商家 H5 后台 → 定稿**商家手机 APP**（用户拍板改为 H5，蓝牙音箱功能保留）
7. **会员**：V1.4 未涉及 → 定稿完整续费体系
8. **新增**：跨店返还、个人身份二维码、审计日志、平台微信支付、单日额度

## 五、待明确项（定稿未给细节，开发前需产品补充）

1. **跨店返还比例/规则**：返还金额如何计算（按实付比例？固定值？）未定义
2. **平台微信支付**：需对接微信支付 Native/JSAPI（外部集成），配置表先建
- **蓝牙音箱**：H5 形态下音箱对接方式（浏览器 Web Bluetooth 受限；可改为商家 H5 页面语音播报或音箱服务端推送）
4. **订单凭证二维码**：加密方案（对称 AES 密钥放平台后台配置）
5. **免费试用/续费与宜必购、团购盲盒关系**：写锁定是否含宜必购下单（定稿第 6.4 条"开盲盒、新建订单、兜底核销、标记退款"未列宜必购，建议一并锁定）
6. **"本店今日您余额最多还可以抵扣 XX 元"**：今日剩余额度需实时计算展示

## 六、开发优先级建议

- **P0（第一批）**：门店级抵扣配置 + 全自动四重 min 计算 + 单日额度表/清零/退款返还 → 会员续费体系 + 写锁定 → 收款模式 A
- **P1（第二批）**：收款模式 B（凭证二维码+确认完成）→ 跨店返还 → 审计日志 → 个人身份二维码 → 平台微信支付配置
- **P2（第三批）**：蓝牙音箱播报 → 订单交易流水号 → 商家 H5 手机适配 + 到期提醒/站内消息
