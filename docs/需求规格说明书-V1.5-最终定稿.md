全套完整需求【最终定稿｜新增续费赠送活动后台可配置】
更新要点：
1、平台后台增加续费营销活动配置：一次性缴满 12 个月（年费）赠送多少个月，软件公司自由设置赠送月数，代码不写死；

3、商家 APP 续费页面动态展示活动文案；

总述
1、两套收款模式，商家后台开关二选一，优惠业务逻辑完全共用，仅收款交互不一样
模式 A：商家上传自己的营业收款码图片；用户长按收款码，手动输入实付金额付款，付款后回到 H5 提交完成订单（消费资金全部进入商家，平台不碰消费资金）
模式 B：平台生成一次性订单凭证二维码（仅订单核验，不是付款码，不能收钱）；商家扫码枪先扫凭证码核对优惠与实付，再扫顾客微信 / 支付宝付款码收款；商家在商家 APP 点击【订单确认完成】闭环订单（消费资金全部进商家账户，与平台无关）
2、优惠计算顺序固定：先盲盒优惠，再余额抵扣，折上折，顺序不可颠倒
盲盒二选一产出：折扣（如 7 折） / 固定立减优惠券，不会同时产出两种
3、余额抵扣全部由系统自动计算，用户、商家均不需要手动输入抵扣金额
4、商家门店独立两项配置，门店之间完全隔离互不干扰：
①余额抵扣百分比（计算基数为盲盒优惠之后的金额；填 0 = 本店禁止余额抵扣）
②本店单用户单日余额抵扣总上限：单个用户一天内在该门店余额累计最多抵扣金额
5、系统组成：用户 H5、商家手机 APP（支持蓝牙音箱文字转语音播报）、软件公司平台管理后台；
区分两笔资金：
①顾客消费付款：钱直接给到商家，平台不参与、不配置商家任何支付密钥；商家上传自己营业收款二维码即可。
②商家向平台交年费续费：这笔付费走平台自身的微信支付；在软件公司的平台后台配置平台自己的微信商户号、AppID、API 密钥、证书。
6、商家会员续费体系：免费试用时长由平台后台可配置（可设 1 个月、2 个月等，不写死）；免费到期之后仅支持按年续费，不支持按月付费；月单价平台后台可配置，年费 = 月单价 ×12；另外后台可配置年费活动：缴满 12 个月赠送 N 个月，活动可开关；会员过期业务写操作锁定，历史数据可读。
7、异常兜底机制：用户关闭页面、离开未提交订单等异常场景，商家可在商家 APP，通过「扫描用户个人身份二维码」或者「输入手机号」查询用户，系统自动计算抵扣金额，商家点击确认即可完成抵扣、核销券；无需用户同意；全部人工操作永久留存审计日志，平台后台可撤销商家违规操作，恢复余额、券状态。
8、退款：退款业务标记操作全部由商家在自己手机商家 APP 完成；平台后台只做查询审计，不能发起退款；支持三种查询订单方式：扫用户个人身份二维码、手机号查询、商家本店订单列表筛选；仅做全额退款，暂不支持部分退款；真实资金退款，商家自行登录自己微信 / 支付宝商户后台操作原路退款，平台不介入资金链路。
9、跨店消费返还余额：订单闭环完成（自动完成 / 商家人工处理完毕）系统自动发放返还余额，推送用户手机弹窗；商家音箱不播报该消息；订单退款时同步扣回已经发放的跨店返还余额。
10、硬性约束：正常消费场景，无论自动还是人工操作，禁止产生负余额；只有退款回滚场景允许台账负余额；每日 0 点，每个用户在每家门店的单日抵扣额度全部清零重置。
11、支付密钥说明：只在软件公司平台后台配置平台自身微信支付参数（用于收取商家年费）；商家端没有密钥配置入口；商家营业收款资金与平台无关，平台不去管理商家微信、支付宝密钥。
一、核心计算公式（开发严格按顺序执行）
情形 1：盲盒开出折扣（例 7 折）
盲盒后金额 = 订单原价 × 盲盒折扣
情形 2：盲盒开出立减优惠券
盲盒后金额 = max (订单原价 − 盲盒券面额，0)
特殊边界：盲盒后金额 = 0（免单），余额抵扣直接等于 0，实付 0 元，不再计算余额抵扣
理论余额抵扣 = 盲盒后金额 × 商家设置余额抵扣百分比
最终实际余额抵扣 = min (
①用户账户可用余额，
②理论余额抵扣，
③本店单人单日抵扣上限 − 用户今日本店已累计抵扣，
④盲盒后金额
)
最终实付现金 = 盲盒后金额 − 最终实际余额抵扣

六、商家续费-会员有效期模块
重点：商家向平台交年费，这笔付费使用平台自身微信支付，密钥配置在软件公司平台后台，商家端看不到、不用配置。
重要：免费试用时长、会员月单价、年费赠送活动，全部由平台后台配置，代码不写死固定数值。
6.1 核心业务规则
1、新开通商家：免费试用时长由平台后台配置（单位：天），从商家账号激活开通当天开始计时；例：配置 30 天 = 1 个月、配置 60 天 = 2 个月。
2、免费试用到期之后，只能按年续费，不支持按月付费；会员月单价由平台后台配置；年费 = 月单价 × 12。
举例：后台设置月单价 150 元，则年费 1800 元；后台改成 200 元，年费自动 2400 元。
3、年费赠送活动配置规则（后台全局）
①活动开关：启用 / 关闭；关闭时不赠送；
②缴满 12 个月年费赠送 XX 个月，后台填写赠送月数（填 0 代表不送）；
③生效范围：仅对开启活动之后新提交的续费订单生效；已经完成续费的历史订单不受改动，不会追加赠送月份；修改活动参数不回溯老订单。
4、续费成功有效期计算：
缴纳 12 个月月费（年费）：基础增加 12 个月会员时间；如果活动开启，则额外叠加后台配置的赠送月数。
5、到期未续费 / 续费失败：
①所有写操作业务功能锁定：盲盒 H5 不可访问、新建订单、开盲盒、兜底核销、标记退款全部禁止操作。
②历史订单、流水、账单、导出功能保留可读，可以正常查看、导出，不可新增业务。
6、续费支付：商家 APP 生成续费支付订单，调用平台的微信支付，跳转微信完成付款，钱款进入平台；商家不需要提供任何支付密钥。
7、有效期叠加逻辑：
免费期内续费：年费（含赠送月份）在免费期结束之后开始计算。
付费未到期续费：在原有到期时间基础向后叠加【12 个月 + 赠送月数】，不覆盖原有有效期。
已经过期后续费：从续费成功当天起生效【12 个月 + 赠送月数】。

配置项：平台微信商户号、AppID、API 密钥、支付证书；

2、全局套餐 & 营销活动参数配置（全部可改，不对历史已续费订单生效）
①商家免费试用天数：输入数字（例如 30）
②会员每月单价：输入数字（例如 150），系统自动计算展示年费 = 月单价 ×12
③年费赠送活动：活动开关【开启 / 关闭】，赠送会员月数（数字，0 = 不赠送）
规则：修改以上全部配置，只对之后新开通商家、新续费订单生效；已经开通、已经续费完成的商家不受影响，不改变他们已有的有效期、费用、赠送月份。
3、商家会员管理列表：账号、会员状态、免费起始时间、付费有效期起止、剩余天数。
4、续费订单管理：订单号、商家、金额、支付状态、购买时长、赠送时长、总增加时长、有效期、支付时间，支持导出。
5、后台可手动调整商家有效期（可以手动增加赠送月份），所有人工调整操作留存审计日志。
6.4 权限校验规则
后端每一个业务写接口强制校验商家会员有效期：
- 会员已过期：开盲盒、新建订单、兜底核销、标记退款等写操作直接返回提示：“会员已到期，请完成年费续费后再使用该功能”。
- 查询类接口（订单、流水、导出账单）不受限制。
七、商家 APP 完整功能清单
1、收款模式开关：模式 A 上传收款码 / 模式 B 扫码枪核验，二选一。
2、门店参数配置：余额抵扣百分比、本店单人单日余额抵扣上限；百分比填 0 代表本店禁止余额抵扣。
3、蓝牙音箱配对、音量调节、播报开关；接收平台事件，文字转语音播报。
4、订单相关：
4-1 模式 B 专用按钮：【订单确认完成】
4-2 兜底入口：扫用户个人身份二维码 / 手机号查询用户，系统自动算抵扣，商家点确认完成抵扣核销
4-3 订单列表，查看本店全部订单；三种定位订单方式，点击【标记退款】完成业务退款
5、订单详情展示商家自己的微信 / 支付宝交易流水号，便于商家去商户后台办理资金退款。
6、订单流水，支持导出 Excel，用于线下结算。
7、会员续费模块：会员状态展示、立即续费、续费记录、到期弹窗与站内消息提醒；活动文案由后台动态输出。
商家 APP 没有任何微信、支付宝密钥配置入口。
八、平台管理后台完整功能清单（软件公司后台）
1、商家信息管理：查看每家门店抵扣百分比、单日抵扣上限、收款模式、会员状态、有效期。
2、平台自身微信支付参数配置页：商户号、AppID、密钥、证书，仅超级管理员可见，脱敏显示密钥。
3、全局套餐 & 营销活动配置：设置商家免费试用天数、会员月单价；年费赠送活动开关、赠送月数；自动计算年费；修改仅对新开通、新续费订单生效，历史商家不受影响。
4、人工操作审计日志：记录商家每一笔手动抵扣核销、标记退款、后台人工调整有效期；字段包含门店、操作账号、操作时间、用户、各项金额；平台后台可撤销商家违规人工操作，恢复余额、券状态。
5、全平台订单流水、退款记录、续费订单查询、导出；续费订单要区分购买时长、赠送时长。
6、盲盒奖品池配置：折扣档位、立减优惠券档位配置。
九、开发重点检查清单（逐条校验）
1、计算顺序严格：先盲盒优惠（折扣 / 立减券），再余额抵扣；余额抵扣基数是盲盒优惠之后的金额，不是订单原价，实现折上折；盲盒后金额为 0，余额抵扣直接为 0。
2、余额抵扣四重条件取最小值，系统全自动计算，用户、商家均不需要手动填写抵扣金额。
3、门店配置完全隔离：A 店抵扣比例、单日额度，不影响 B 店；每日 0 点清零每家门店下用户的单日抵扣额度。
4、订单退款，本单占用的当日抵扣额度必须返还恢复。
5、模式 B 平台生成的订单凭证二维码仅做核验，不能收钱；收款依旧扫微信支付宝付款码；订单闭环由商家 APP【订单确认完成】按钮触发，不靠 H5 用户提交。
6、正常消费场景禁止余额变为负数，只有退款回滚才允许台账负余额。
7、商家所有人工操作全部留存审计日志，平台后台可撤销违规记录。
8、跨店返还余额，仅订单闭环完成后发放，只推送用户手机弹窗，商家音箱不播报；订单退款同步扣回跨店返还余额。
9、退款业务标记入口只在商家手机 APP；平台后台仅查询审计，不能发起退款；真实资金退款由商家自行在商家自己微信、支付宝商户后台处理，平台不触碰消费资金链路。
10、用户 H5 个人中心生成平台内部个人身份二维码（仅识别用户身份，不是付款码）；商家扫码之后展示该用户本店全部历史订单，商家手动选定订单再标记退款，扫码不会自动退款。
11、退款只支持全额退款，暂不开发部分退款功能。
12、商家免费试用天数、会员月费单价全部在平台后台配置，代码不能写死；年费自动 = 月单价 ×12；到期后仅支持按年续费，不支持按月付费；配置修改只对新开通、新续费订单生效，历史已付费商家不受改动。
13、年费赠送活动后台可开关、赠送月数可配置；仅对新续费订单生效，不回溯老订单；续费订单记录区分购买时长、赠送时长；商家 APP 展示活动文案。
14、会员到期未续费：新增业务写操作全部锁定禁止；历史订单、流水、账单、导出保持可读；续费成功有效期向后叠加，不会直接覆盖原有有效期。
15、后端所有业务写接口强制校验商家会员有效期，到期拦截业务操作；平台后台可人工调整商家有效期并留存操作日志。
16、只有平台后台配置平台自己的微信支付（用于收商家年费）；商家端没有密钥配置页面；顾客消费的资金走商家自己的收款码，平台不配置、不管理商家任何支付密钥、商户号。
