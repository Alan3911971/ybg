【G13 反迎合型工作原则（2026-09-10 起强制执行）】
1. 先检查问题有没有错误前提、逻辑跳跃和信息缺失，不盲目接需求
2. 不迎合用户，独立判断；用户说错了直接指出，不顺着说
3. 区分事实、推测和主观观点：事实=已查证（查库/查日志/查代码），推测=标"可能/待验证"，观点=明确标注"我认为"
4. 涉及数字、人物和结论时尽量核实来源，不靠记忆和印象
5. 不同意就直接指出，并给出依据、风险和替代方案，不绕弯子
6. 主动补位：提醒用户忽略的变量、成本和偏差（如测试限制未移除、token泄露、配置未生效等）
7. 典型应用场景：
   - 用户说"又变成不调api模式了"→先查数据库pay_mode确认没变，再定位降级逻辑bug，不盲目改配置
   - 用户说"改下8.8立减券"→发现有两个重复的，主动问删哪个
   - 微信JS-SDK报错→区分"接口正常"和"配置缓存未生效"，明确说需要等5-10分钟

【G17 蓝牙打印规范（2026-09-16 起强制执行）】
1. 打印机型号：DP80S（德佟DETONGER 80mm热敏标签打印机），用户自有APP"微打"打印正常
2. 蓝牙连接优先级：
   - 必须优先用标准SPP UUID（00001101-0000-1000-8000-00805F9B34FB）连接
   - 自定义UUID（e5b152ed-...）是LPAPI协议通道，不支持ESC/POS，禁止用于打印
   - 连接前用fetchUuidsWithSdp获取设备支持的所有UUID，按标准SPP→自定义UUID顺序尝试
3. 打印指令规范（ESC/POS兼容模式）：
   - 初始化：ESC @ (0x1B 0x40)
   - 文字：GBK编码 + 0x0A换行，中文必须用GBK不能用UTF-8
   - 二维码：Canvas绘制位图(280x280) + GS v 0指令(0x1D 0x76 0x30 0x00)，1位/像素MSB优先
   - 走纸：ESC d n (0x1B 0x64 n)，打印后走纸6行（约1厘米）
   - 打印顺序：先文字（店铺名倍宽倍高→副标题→走纸1行）→再二维码位图→最后走纸6行
4. 连接稳定性：
   - 连接成功后的测试写入（换行符）必须放在独立try-catch中，失败不能断开主连接
   - printText/printQR中必须检查btOut为null时重新获取输出流
   - 禁止在连接成功后立即发送大量数据测试，会导致Broken pipe
5. AndroidBridge接口必须与H5调用完全匹配：
   - isAvailable() / isBluetoothEnabled() / isConnected() / getConnectedDeviceName()
   - hasPermission() / requestPermission() / openBluetoothSettings()
   - showDevicePicker() / connect() / connectPrinter(mac) / disconnectPrinter()
   - printText(text) / printQR(url, shopName)
   - speak(text) / speakUrl(url)
6. 坑：德佟DP80S等标签打印机有双蓝牙通道，自定义UUID通道是LPAPI协议不支持ESC/POS，必须用标准SPP通道

【G35 中奖弹屏·场景引擎规范（2026-10-26 定版，取代早先"4 模式共用一张卡片"版本）】
（2026-10-27 重写：旧版仍描述 `detectWinMode` 正则判奖品名 + 5 个 wav + 35 项校验，与实现不符，照旧版执行会走错路）
1. **场景由中奖内容决定，4 套完全独立的舞台 DOM**：折扣券=价签吊牌 `dc-*`｜立减券=票券票根 `cp-*`｜余额=钱包卡片+金币 `bl-*`｜免单=全免印章 `fr-*`。是 4 个场景，不是同一张卡片换配色。
2. **场景 → 档位**：`WIN_TIER_RULES` 按 prizeType 各定阈值（折扣券折数越小档越高，阈值反排）。t1 劲爆 / t2 超值 / t3 幸运，控制 tone（配色强度）/ glow / props（道具数）/ hold（停留）/ scale / 音效文件 `{scene}_{tier}.wav`。
3. **数据来源必须是结构化字段**：`prizeType`（1折扣 2立减 3余额 4免单 5谢谢参与）/ `prizeValue` / `phoneTail` / `customerSeq`。**禁止用正则从 content 猜奖品类型**（旧 `detectWinMode` 已废弃）。`recentWins` 只认 `is_primary=1`。
4. **每种场景必须同时具备四件套**：配色（卡片渐变 + 底色墨色 + 波纹色）、文案（英文 kicker + 中文标题 + 领取提示）、动效（波纹数量/间隔 + 流光）、音效（音型 + 音色 + 时长）。只改颜色不改音效、或只改音效不改文案，都算不合格。
5. **弹屏底色必须完全不透明**：内圈用场景墨色、外圈用深底，`radial-gradient(ellipse at center, ink, outer 72%)`，两个色都必须是不透明色。任何"内圈半透明"的写法都会把队列区和广告画面透出来。
6. **版式契约**：`.sc-kick` top 46、`.sc-title` top 78（标题带到此为止），主舞台一律以 **top:400px** 为心。舞台中心按 44~45% 定位会让卡片顶边压住标题。弹屏时码已隐藏，底部信息条 left/right 70。
7. **原生层必须在弹屏期间让位**：原生层永远盖在 WebView 之上。广告 TextureView 靠 `AndroidTV.setAdVisible(false)`、**二维码 ImageView 靠 `AndroidTV.setQrVisible(false)` 一起藏掉**（v1.6.0 起）。老 APK 无 setQrVisible，页面须在右下保留 184×184 空位兜底。
8. **状态守卫必须判断"调用那一刻"**：任何 `setTimeout` 延后触发的原生调用（如 `AndroidTV.playVideo`），守卫要写在回调内部，不能写在注册处。
9. **音效与语音排队规则**：`playFx` 独立通道 → 语音延后 600ms（可叠音）；老 APK 只有 `speakUrl` 共用通道 → 语音延后 = 音效时长 + 520ms。绝不共用通道且同时发声。
10. **音效文件规范**：`/h5/fx/{scene}_{tier}.wav`，**中奖音效共 12 个 = 4 场景 × 3 档**（非旧版的 5 个）。44.1kHz / 16bit / 单声道，峰值 0.88，末尾 30ms 必须淡出（否则播放末尾爆音）。生成脚本 `_gen_win_fx.py`，校验脚本 `_check_win_fx_wav.py`（Goertzel 测音高，阈值用相对能量：应有音 ≥0.05% 最强音，不该有的音 ≤0.5%）。
    【口径澄清 2026-10-27 实测】知识图谱曾记"/h5/fx/*.wav 17 个" —— 那是**目录文件总数**（含叫号等非中奖音效），
    不是中奖音效数。生成脚本 `_gen_win_fx.py` 明确产出 discount/coupon/balance/free × t1/t2/t3 = 12 个。
    说"有几个音效"时必须区分这两个口径，否则 12 与 17 会互相打架。
11. **4.4 WebView 没有 Web Audio API**（AudioContext / webkitAudioContext 均 undefined）：电视端音效只能走「服务端 WAV + APK 原生 MediaPlayer」，禁止在页面里用 AudioContext。

【G36 大屏双模式与生产库迁移铁律（2026-10-27 起强制执行）】
1. **生产 MySQL 是宿主机原生宝塔，不是 docker 容器**：`docker ps` 没有 `ibigou-mysql`，app 也是 `/www/wwwroot/ybgtc.com/ibigou.jar` 裸进程。**任何迁移/SQL 禁止用 `docker exec ibigou-mysql`**（必然失败），必须用宿主机 `/usr/bin/mysql` 客户端 + `/www/wwwroot/ybgtc.com/.env` 里的 `IBIGOU_DB_HOST/PORT/USER/PASSWORD/NAME`。密码含特殊字符用 `-p"'$PW'"`。
2. **迁移必须真幂等，禁止假幂等**：`ALTER ... || echo "已存在"` 会把连接失败、容器不存在等**真实错误**都说成"已存在"，导致列没加上却显示成功（G114 已踩）。正确写法：先 `SELECT COUNT(*) FROM information_schema.COLUMNS WHERE TABLE_NAME='<表>' AND COLUMN_NAME='<列>'`，为 0 才 ALTER，且**不要吞 stderr**。
3. **部署脚本的"加列"与"校验"两处要同步改**：只改一处会留下第二次踩坑（本次 `_deploy_win_scene.py` 2.5/5.5 均已修）。改完 `python -m py_compile` 确认。
4. **验证接口字段别用 json.loads**：curl 返回体带额外尾部数据会报 `Extra data`，造成"字段缺失"的假阴性。判字段存在用 `grep -c "<字段名>"`。
5. **大屏模式切换（`merchant_queue_config.tv_mode`）**：`call`=叫号屏、`activity`=盲盒活动屏。切换走商家后台 → `POST /api/merchant/config/tv-mode`；**切换后必须重启大屏 App**（WebView 只启动时拉一次 tv.html）。模式决定左区布局与二维码落点，activity 模式要 `AndroidTV.setQrVisible(false)` 隐藏原生码防双码。**该能力不改 APK**，不要为此重新打包。
6. **商家后台等 H5 页面要单独传磁盘**：`h5/*` 真身是磁盘 `/www/wwwroot/ybgtc.com/h5/`，重打 jar 不会覆盖磁盘文件。改了 `static/h5/**` 的页面，除打包外还要单独 sftp 覆盖磁盘（先备份）。
7. **无 token 访问需鉴权接口返回 HTTP 200 + `{"code":-1,"msg":"请先登录"}`** 属正常，不是 404、不是未注册，不要据此判定部署失败。

【G37 工作面板机制（2026-10-27 起强制执行）】
