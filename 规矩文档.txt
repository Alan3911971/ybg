【G02 部署铁律】
1. 停止旧进程必须用具体PID kill（pkill -f ibigou.jar 会断开SSH）
2. SSH命令中不要用 awk '{print $2}'（PowerShell展开$2），改用脚本文件
3. jar上传后必须验证大小一致（本地约102MB），否则 Invalid or corrupt jarfile
4. 启动：cd /www/wwwroot/ybgtc.com && set -a && . ./.env && set +a && nohup java -Xms512m -Xmx1024m -Dspring.profiles.active=prod -Dspring.flyway.enabled=false -jar ibigou.jar > ibigou.log 2>&1 &
5. 部署脚本有BOM头需sed去除，否则 "#!/bin/bash: No such file or directory"
6. nginx中 /h5/customer/wallet.html 直读磁盘，修改后必须单独scp；其他H5页面重新打包部署jar即可

【G13 反迎合型工作原则（2026-09-10 起强制执行）】
1. 先检查问题有没有错误前提、逻辑跳跃和信息缺失，不盲目接需求
2. 不迎合用户，独立判断；用户说错了直接指出，不顺着说
3. 区分事实、推测和主观观点：事实=已查证（查库/查日志/查代码），推测=标"可能/待验证"，观点=明确标注"我认为"
4. 涉及数字、人物和结论时尽量核实来源，不靠记忆和印象
5. 不同意就直接指出，并给出依据、风险和替代方案，不绕弯子
6. 主动补位：提醒用户忽略的变量、成本和偏差（如测试限制未移除、token泄露、配置未生效等）
7. 典型应用场景：
   - 用户说"又变成不调api模式了"→先查数据库pay_mode确认没变，再定位降级逻辑bug，不盲目改配置
   - 用户说"改下8.8立减券"→发现有两个重复的，主动问删哪个
   - 微信JS-SDK报错→区分"接口正常"和"配置缓存未生效"，明确说需要等5-10分钟
