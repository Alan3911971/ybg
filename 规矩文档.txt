【G13 反迎合型工作原则（2026-09-10 起强制执行）】
1. 先检查问题有没有错误前提、逻辑跳跃和信息缺失，不盲目接需求
2. 不迎合用户，独立判断；用户说错了直接指出，不顺着说
3. 区分事实、推测和主观观点：事实=已查证（查库/查日志/查代码），推测=标"可能/待验证"，观点=明确标注"我认为"
4. 涉及数字、人物和结论时尽量核实来源，不靠记忆和印象
5. 不同意就直接指出，并给出依据、风险和替代方案，不绕弯子
6. 主动补位：提醒用户忽略的变量、成本和偏差（如测试限制未移除、token泄露、配置未生效等）
7. 典型应用场景：
   - 用户说"又变成不调api模式了"→先查数据库pay_mode确认没变，再定位降级逻辑bug，不盲目改配置
   - 用户说"改下8.8立减券"→发现有两个重复的，主动问删哪个
   - 微信JS-SDK报错→区分"接口正常"和"配置缓存未生效"，明确说需要等5-10分钟

【G14 Spec Kit 规格驱动开发强制规范（2026-09-11 起强制执行）】
1. 工具：specify-cli v1.0.7+，已安装在 C:\Users\Administrator\.local\bin\specify.exe（已加入系统PATH）
2. 项目已初始化：D:\workspace-java\ybg-master（.github/skills/ + .specify/ 已就绪，集成 GitHub Copilot）
3. 所有新功能开发（非紧急bug修复）必须走 Spec Kit 流程：
   ① $speckit-constitution — 建立/更新项目原则（每个项目一次）
   ② $speckit-specify — 定义需求规格（做什么、为什么，不写技术栈）
   ③ $speckit-clarify — 澄清模糊需求（可选但推荐，在plan之前）
   ④ $speckit-plan — 创建技术实现计划（技术栈、架构、接口）
   ⑤ $speckit-tasks — 拆分为可执行任务清单
   ⑥ $speckit-implement — 按任务执行实现
   ⑦ $speckit-converge — 验证实现与规格一致，不一致则补任务
4. 规格文档（.specify/ 下生成的 spec/plan/tasks）必须保留，作为开发依据和验收标准
5. 紧急bug修复可跳过 Spec Kit，但修复后必须补记录到采坑日志
6. 与 G12 知识图谱的关系：Spec Kit 的 tasks 完成后，必须同步更新知识图谱（模块/接口/表名/代码位置）
7. 与 G11 双向备份的关系：Spec Kit 生成的 .specify/ 和 .github/skills/ 目录必须纳入备份范围
8. 调用方式：在 Copilot 中用 $speckit-xxx 调用；命令行用 specify --help 查看

【G15 演示验证与主动修复铁律（2026-09-12 起强制执行）】
1. 每次修改代码、更新服务器后，**必须操作演示给用户看**，不能只说"已完成"就结束
2. 演示方式：用浏览器打开对应页面，截图/录屏展示修改效果，确认功能正常
3. 演示过程中发现bug，**必须主动解决**，不能等用户指出才修
4. 演示验证清单：
   - 页面是否正常加载（无白屏/报错）
   - 新增功能是否按预期工作
   - 修改的功能是否生效（对比修改前后）
   - 相关联功能是否受影响（回归测试）
   - 控制台是否有JS报错
   - 后端接口是否返回正确数据
5. 发现bug后的处理流程：
   - 立即定位根因（查日志/查代码/查数据库）
   - 修复后重新部署
   - 再次演示验证，确认bug已解决
   - 记录到采坑日志
6. 典型反例（禁止）：
   - "已部署，你刷新看看" → 必须自己先验证再给用户看
   - "应该没问题了" → 必须实际操作确认
   - 用户发现bug后才修 → 必须演示时主动发现并修复
7. 与 G12 四文档更新的关系：演示验证通过后，再更新四文档（采坑日志/共享记忆/知识图谱/规矩文档）

【G16 完整闭环工作规范（2026-09-12 起强制执行）】
1. 任何任务必须做到**完整闭环**，不能半途而废，不能只做一半
2. 完整闭环8步流程（缺一不可）：
   ① **需求理解** — 确认用户真实需求，有歧义先问清，不盲目开工
   ② **代码修改** — 本地修改代码，确保语法正确、逻辑完整
   ③ **构建部署** — 后端mvn打包+替换jar+重启，前端scp到服务器+nginx配置
   ④ **测试验证** — 接口测试(curl)、页面测试(浏览器)、回归测试(相关功能)
   ⑤ **演示给用户** — 用浏览器实际操作演示，截图/录屏展示效果（G15）
   ⑥ **主动修复bug** — 演示中发现问题立即修，修完再演示（G15）
   ⑦ **四文档更新** — 采坑日志→共享记忆→知识图谱→规矩文档（G12）
   ⑧ **双向备份** — GitHub推送+NAS同步，报告commit号（G11）
3. 闭环完成标志：用户确认功能正常 + 四文档已更新 + 双向备份已完成 + 已向用户报告
4. 禁止的"半闭环"行为：
   - 只改代码不部署
   - 只部署不测试
   - 只测试不演示
   - 只演示不更新文档
   - 只更新文档不备份
   - 用户说"有问题"才回头修（应该主动发现）
5. 任务中断处理：如因外部原因（如用户去吃饭、网络中断）无法完成闭环，必须明确记录"未完成项"和"待续步骤"，下次继续时从断点接上
